# 渐进重构

目标是保持现有 CLI、JSON、YAML、SQLite 数据和 Rust 公共接口兼容，逐步分离配置、学校协议、应用编排与本地存储。继续使用单个 crate 和同步运行模型；当前没有新增多宿舍监控或新查询服务。

## 已完成的第一批改动

- `lib.rs` 改为公共接口入口；原有导出通过重新导出保留。
- `domain` 保存精确读数和位置，`event` 保存现有输出契约，`storage` 承接历史、迁移和冷却操作。
- `dorm` 按请求、协议、目录解析和认证查询编排分开。配置模块不再实现网络目录解析；公开的 `Settings::dorm_request` 保留为兼容适配。
- `auth` 按 Token 模型、缓存和锁、设备身份、CAS 回调、OAuth 请求及应用服务分开。
- 通用原子文件写入进入 `local`，后台管理不再为了写文件依赖认证模块；公开的 `auth::secure_write` 保留为兼容适配。
- 配置结构读取与功能校验分开。`Settings::load` 和 `check-config` 保留全量校验，各功能内部读取后校验所用配置。
- 认证锁使用有期限的非阻塞轮询；daemon 可取消锁等待，取消不生成失败读数和通知。刷新与缓存更新仍由同一个跨进程锁保护。

回归测试使用临时目录和假凭据，覆盖无关配置语义错误、全量校验、查询兼容、通知独立校验、锁等待期限、缓存保留以及持锁期间停止后台进程。HTTP 多步认证仍使用每次请求的超时，尚未引入整个认证操作的总时间预算。

第一批验证结果：`bash scripts/check.sh` 通过，格式检查、81 个普通测试和 Clippy 均通过；1 个原生服务生命周期测试按默认设置跳过。本次没有重新注册系统服务，也没有访问学校或发送真实推送。

## 已完成的第二批改动

- daemon 按实例文件/控制、状态契约、日志、运行参数、工作循环、状态查询和通知测试拆分，原有 `daemon` 导出保持可用。
- `main.rs` 只负责参数解析和退出码；`cli` 按认证、后台管理、查询、历史、旧 watch 及输出分开。
- `HistoryStore` 提供历史记录、近期查询和旧提醒冷却操作；CLI 与后台工作循环不再编写历史 SQL。
- 通知投递通过 `DeliveryStore` 执行持久化和事务，投递引擎保留重试、冷却和渠道轮询策略。公开的原 `DeliveryEngine::new` 保留，新工作循环使用 `for_history`。
- 表结构初始化/迁移集中在 `storage/migrations.rs`；网络发送不持有数据库事务，成功冷却与接受状态仍原子提交，发送预算仍在请求前写入。

第二批验证结果：格式检查、83 个普通测试和 Clippy 通过，原生服务生命周期测试仍按默认设置跳过。额外比较了 10 组 CLI 帮助输出和 18 条生产 SQL，均与重构前一致。历史兼容测试覆盖旧数据库迁移、位置字段、失败记录输出和不存在的历史路径。

## 已完成的第三批改动

- 内部 `Observation` 明确区分成功与失败，成功保留 `Reading`、`Decimal` 和时间类型，失败不能携带电量；公开的 `Event` 和 `Sample` 保留为兼容输出。
- 后台工作循环使用 `WorkerState` 和状态枚举，保存状态时转换成原 `RuntimeState`。启动时保留旧成功快照，不重新解析或丢弃其中的历史字符串。
- SQLite 投递状态使用枚举解码/编码，保留原状态值和表结构；未知状态会作为脱敏存储错误处理。
- 新内部通知路径使用精确阈值计算 topic，原 `observe(Event, ...)` 作为兼容适配继续可用。两条路径共享冷却、重试和恢复策略。

第三批验证结果：格式检查、89 个普通测试和 Clippy 通过。新增测试检查精确小数和 JSON 契约、失败与登录处理策略、失败时保留旧余额、恢复清除错误、旧快照保留、SQLite 状态兼容，以及新旧通知路径的 payload/冷却/重试等价性。

## 已完成的第四批改动

- `source::ElectricitySource` 统一读取上下文、精确读数、已解析目标和失败结果；宿舍与空调保留各自的目标类型。
- `DormSource` 使用原有认证与重试流程，监控通过来源接口读取，替换查询来源无需修改阈值、历史或通知策略。
- `AirconSource` 接入实际空调查询；HTML 解析保留 `Decimal`，仅在原 `AirconReading` 输出边界转成字符串。
- `ReadContext` 提供请求超时和合作式取消；监控取消前后均不生成样本。已开始的 HTTP 请求仍使用原请求超时，显式短信登录行为保持原样。
- 原查询函数、空调输出、监控宿舍范围与认证策略保持兼容。来源接口支持其他目标类型，现有事件采样仍要求宿舍 `Location`。

第四批验证覆盖替代来源的精度、阈值比较、失败目标、读取前后取消，以及真实来源在缺少凭据/目标时的本地失败。格式检查、93 个普通测试和 Clippy 均通过，原生生命周期测试按默认设置跳过。

## 已完成的第五批改动

- 调度实现集中到 `monitor/schedule.rs`，用 `Cadence` 明确表达周期从开始还是完成计时。
- daemon 保留开始到开始的调度、错过周期跳过和休眠/时钟回拨检查；旧 watch 使用完成到开始的单调时间等待，保留查询耗时后再等待完整周期的行为。
- 测试用超过周期的查询验证两种调度差异，原阈值比较、错误处理和通知行为保持不变。

第五批验证：格式检查、94 个普通测试和 Clippy 均通过，原生生命周期测试仍按默认设置跳过。

## 已完成的第六批改动

- 后台管理适配按 `backend/linux.rs`、`macos.rs`、`windows.rs` 分开，平台分派与共同状态映射保留在 `backend.rs`。
- 每个平台集中管理自己的可用性检查、启动、停止、卸载和状态读取；Windows 的 PowerShell 编码与进程身份核验留在 Windows 适配内。
- 注册校验、实例锁、生命周期编排和服务定义渲染保持原职责，不新增服务管理框架。三个后端在普通测试中都通过假管理器验证。

第六批验证：格式检查、94 个普通测试和 Clippy 通过；额外执行 macOS 当前用户 launchd 原生生命周期测试，1 个测试通过，临时服务已卸载。Linux、Windows 和 Intel macOS 的原生生命周期结果仍需对应 CI runner 确认，不能用本机结果替代。

- 原有 stable 格式检查、普通测试、Clippy、原生生命周期测试和 Docker 检查保持原样。
- 本机使用官方校验和验证的隔离 Rust 1.88.0 工具链，以现有锁文件离线构建并运行 94 个普通测试，全部通过；无需调整依赖和锁文件。
- 工作流 YAML 已解析验证，最低版本矩阵与原生测试步骤保留检查通过。远端矩阵尚未执行，本地结果只代表 Apple Silicon macOS。

## 当前架构评估

本轮计划的七批渐进重构已完成。继续使用一个 crate、同步 HTTP 与 SQLite，符合当前单宿舍监控的规模；没有引入异步运行时或服务注册框架的必要。结构已从大型入口文件转为职责明确的模块。

| 边界 | 当前职责 |
| --- | --- |
| `main` / `cli` | 参数、命令编排、终端输出和退出码 |
| `domain` / `event` | 精确读数与位置；兼容的 JSON/历史输出契约 |
| `source` | 读取接口、超时/取消上下文、宿舍和空调来源适配 |
| `dorm` / `aircon` / `auth` / `cas` | 学校协议、认证与缓存；避免泄漏原始响应和凭据 |
| `monitor` | 观察结果、阈值、调度与通知投递策略 |
| `storage` | SQLite 表结构、迁移、历史与投递事务 |
| `notification` | 渠道配置、发送与网络错误分类 |
| `daemon` | 实例、状态、日志、工作循环与系统服务管理 |

模块内的策略与状态聚合更完整，SQL 和平台命令也集中到了各自边界。监控通过来源接口读取，投递策略通过渠道接口发送；配置、网络协议和命令输出的职责更加清晰。公共兼容入口仍保留，当前不以删除旧 API 换取形式上的分层。

扩展新查询来源可实现 `ElectricitySource`，新通知渠道可沿用现有发送接口，后台平台逻辑独立维护。现有监控仍只接受宿舍 `Location` 和单配置实例；多目标调度、空调后台监控需要另行设计目标身份、通知状态与配置模型，不能仅增加一个来源实现就自动获得。

跨平台实现仍依赖对应用户服务管理器；容器和不支持原生管理的环境使用 `daemon run`。本机已经验证 Apple Silicon macOS，其他平台由 CI 进行实际编译和生命周期测试。多步认证仍按每次 HTTP 请求设置超时，合作式取消检查操作边界；整个认证总时间预算、真正并行监控和完整网络中断不属于本轮已实现能力。
